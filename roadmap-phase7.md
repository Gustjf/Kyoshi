# Phase 7: Pabu (keep in touch) — the detailed plan
Planned with the owner on 2026-10-02 (14 questions; the answers are folded into Decisions). Read it when building Phase 7,
after the root `CLAUDE.md` (automatic), roadmap.md's top sections and its Phase 7 section, then the files under **Read

days you talked (`talks`) and `last` is worked out from them; `every` gains `"none"` (birthday only); a never-talked

nothing to Momo's inbox; a Birthdays strip and a quick add with chips join the screens; the birthday is typed as month,
day and an optional year. The owner chose a strong model (Opus 5.5) and a plan rather than the roadmap's "straight to
building"; `main` stays, as the roadmap says. Once Phase 7 is ticked in roadmap.md (its Status line holds the decisions),
rename People → Pabu in "The shape of the system" and "What each app sends Momo" there, and delete this file.

## Context
Kyoshi is a life system with Momo (the weekly time budget) at the centre: each app says *what* it needs, Momo decides *when*. Phase 7 adds the last planned feeder, **People**: the people you want to stay close to, each with how often you mean to reach them (every week … every year) and how (a call, a text, a visit). Pabu says who's due; Momo fits them into your "Keep in touch" cards; birthdays land on Momo's board as events. It is the simplest app since Hawky and is modelled on it file for file. Nothing changes in Momo or core.

**Name:** Pabu (Bolin's fire ferret). **Icon:** Lucide's `heart-handshake`, stroke `#f43f5e` (rose). **Width:** 780. **Checkup:** 15 min, no schedule. **Never a dot.**

## Decisions (from the owner, 2026-10-02)
| Topic | Decision |
|---|---|
| Name & icon | Pabu, Lucide `heart-handshake` in rose |
| Cadence | `every`: `week` · `2weeks` · `month` · `quarter` · `year` · **`none`** ("birthday only": never due, never sent to Momo's inbox; the birthday still goes to the board) |
| How | `how`: `call` (30 min) · `text` (10) · `visit` (120); minutes editable per person (5–480). The title in Momo is "Call Mom" / "Text Sam" / "Visit Lee" |
| Talk history | `talks: ["YYYY-MM-DD", …]` per person (newest first, unique, capped at 200). **`last` is derived**: `lastTalk(p, today)` = the newest day `<= today` (a future day from a device with a wrong clock is kept but ignored), not stored. Talked ✓ adds today; ✓ again removes today (undo) |
| Due | last talk + every (`addDays` 7 / 14; `addMonths` 1 / 3 / 12, as `core/meetings.js` `after()`). **Never talked → due = the day they were added** (`at`'s local day; today when `at` is 0). "Due now" = due ≤ today; overdue (red, Momo's flag) = due < today |
| Snooze | none: Momo decides when |
| Birthdays | `birthday`: `"MM-DD"`, `"YYYY-MM-DD"` or `""`. A **Birthdays strip** at the top (next 30 days, hidden when none). A birthday does **not** make the person due. On the board: a 15-min event with **no time** (Momo draws it as Pabu's icon in the day's heading, and as an "any time" row on Today), ✓ once you talked that day. Typed as **three fields**: month dropdown · day · optional year |
| Later group | always open (no fold); birthday-only people at its end, by name |
| Adding | **Quick add** like Hawky: name + Add; chips for every (6) and how (3); defaults month + call. Birthday, note, minutes and talks live in the pop-up |
| Contact details | none (no phone numbers, no import) |
| Groups/tags | none; a flat list: Due now · Coming up (14 days) · Later (birthday-only people at its end) |
| Momo block | one block, **"Keep in touch"**, by time, each person whole |
| How early Momo may place someone | **up to 6 days before due**: `from = addDays(due, -6)` (`WINDOW_DAYS`, as meetings), and `from: null` once overdue (as `core/meetings.js:109` does). Verified in `apps/momo/inbox.js:48`: a block fits when `day >= from && (overdue || day <= due)` |
| Who goes to Momo's inbox | only people with a schedule: their open need, and their talk days as done needs. Birthday-only people send nothing to the inbox (their birthday still goes to the agenda, ✓ when talked that day) |
| Dot | never (`DOT_WHEN_OVERDUE: false` in `app.js`, one line to flip) |
| Sync merge | whole person by `u`, later wins (Hawky's `combine`), deleted people kept as markers |

## How Momo shows what Pabu sends (verified in Momo's code; nothing to change in Momo)
- A Keep in touch need: `apps/momo/inbox.js:48` `fits` → a block titled "Keep in touch" (any case) on a day `>= from` and `<= due` (any day once `due < today`), by time, each person whole; what's left is one "Keep in touch" task in Tasks, labelled e.g. "Keep in touch (Visit Gran from Pabu, overdue)". Momo asks `K.inbox(today, next Sunday)` (`inbox.js:18`) and re-reads every minute and on show.
- A done need (`date`, `done: true`) is placed first on that day's card and **still takes its minutes of the card's room** (`inbox.js:49, 74-75`); one too long for any card that day is dropped quietly, never a task. The card's label says "— done ✓" only when **every** need on it is done (`inbox.js:84 allDone`); otherwise the pop-up lists the done one with "✓ done". Names are joined "Call Mom and Call Ana" (`apps/momo/agenda.js:102 names`).
- A birthday (`time: null`): on the board it is **not** a block in the column but a small icon in the day's heading (`apps/momo/agenda.js:219` `headEventsHTML`: `.col-evs .ev-mark`, `title`/`aria-label` "Kai's birthday (Call), Thu any time, from Pabu", `.done` with ✓ once talked, then a `role="img"` span instead of a button; clicking an open one opens the event pop-up). On Today it is a `.t-row.t-event` with "any time" (`apps/momo/today.js:57,87`), under today's or tomorrow's rows; **a done one is a `div` with a `title` and no `aria-label`** (`today.js:81`), so tests read `title` for done events. Tests target those selectors.
- Pop-up details: Momo's card pop-up (`fromHTML` in `apps/momo/inbox.js:99`) lists each need's title, "✓ done" and its `details` lines, with "Open in Pabu" → `K.inbox.open("pabu", id)` → `A.open(id)`.

## Data
Key `people` (plus core's `sync` and `meetings`). Backup `{ schemaVersion: 1, appVersion, people }`.
```
person: { id, name ≤ 40, every, how, minutes 5–480, talks: ["YYYY-MM-DD", …] (desc, unique, ≤ 200),
          note ≤ 300, birthday: "MM-DD" | "YYYY-MM-DD" | "", deleted, at, u }
```
A deleted person keeps only `id, deleted, at, u` (name "", talks [], note "", birthday "").
Cleaning (`cleanPeople`): `every` and `how` are **kept as stored when id-like** (`/^[a-z0-9]{1,12}$/`), else `"month"` / `"call"`; everywhere they're read, `everyOf(p)` / `howOf(p)` fall back to `"month"` / `"call"` for a value this version doesn't know (a newer version's value survives a round trip through an older copy, as `core/meetings.js:53, 88` does); minutes out of range → that how's default; talks: valid dates only, unique, sorted desc, capped (future days kept, see `lastTalk`); birthday: `cleanBirthday` (`""`, a full `isDate`, or `MM-DD` with a real month/day checked against a leap year so `02-29` passes); drop a person with no name unless deleted; unique ids; `at` must be a positive number below `8.64e15`.

## Edge cases (decided; put the relevant ones in Pabu's CLAUDE.md invariants)
- Feb 29: accepted as a birthday; shown on Feb 28 in a non-leap year (`birthdayIn` clamps to the month's end).
- A name of only spaces: quick add says "Type a name first." and refocuses; the pop-up alerts. Duplicate names are allowed (ids differ).
- A talk day after today: refused in the pop-up; kept by cleaning (another device's clock may be ahead) but ignored by `lastTalk`, so due maths never runs from the future. Talked ✓ only ever adds today.
