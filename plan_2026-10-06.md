## What the owner asked, and how this plan answers it
- **Current data on the phone, the home PC and the work PC, entering only one key.** A private GitHub repository is the meeting point. Each app's data is one encrypted file there (`data/<app>.json`). A device with the key checks the repository every minute and after each change, pulls what other devices saved, merges it the way folder sync already does, and pushes its own changes. The key is one string, pasted once per device (or each time, on a shared computer).
- **Encrypted.** AES-256-GCM through the browser's Web Crypto, a fresh random nonce per save, the data gzipped first. The key never leaves your devices: GitHub holds scrambled files and file names, nothing readable.
- **Decrypt and export in plain text, in the dev menu.** Developer Mode's Cloud block gets *Download decrypted copy* (every app, the same file Export all makes, so Import all takes it back) and *Decrypt a file…* (one file taken from the repository → its plain JSON, or the original photo/PDF). Phase 4 adds a standalone `tools/decrypt.html` that needs nothing but the key, so the data outlives the app.
- **Backup & sync out of the way.** The "Backup & sync" section leaves every app's page. Developer Mode (Ctrl+9, or the DEV badge) holds Export/Import JSON for the app on screen, Export/Import all, the sync folder, and the Cloud block. The only trace on the page is a small cloud glyph in the header saying whether this device is current (the owner's call: D1).

## How it works, in plain terms (for the owner)
You make an empty **private** repository on GitHub (say `kyoshi-data`) and a **token** that may read and write that one repository only. On the first device, Kyoshi's Developer Mode → *Set up a new cloud…* takes the repository's name and the token, makes a random secret, and shows you **one key string** to keep in your password manager. On every other device you paste that key once (*Enter key…*), and the device fills up from the cloud. From then on each device keeps itself current on its own. The key string holds the repository's name, the token and the secret; the secret is what scrambles the files, so a new token (they expire) never changes the files, and GitHub (or anyone who sees the repository) can't read them. Lose the key and the cloud copy is unreadable; your devices' own copies and your exports are untouched.

## Other ideas weighed (and why this one)
- **Keep the sync folder (Syncthing).** It stays, in Developer Mode, but it needs a folder-sharing tool on every device, Chrome or Edge, and an always-on peer; it can't reach a work PC that forbids such tools or an iPhone. GitHub's API works from any browser on any network that allows github.com.
- **A GitHub Gist.** "Secret" gists are public to anyone with the link, and gists hold no folders. A private repository is the right primitive.
- **Google Drive / Dropbox / OneDrive.** They need an OAuth app with a client id and token refreshes, which a server-less page can't keep secret; more moving parts for ten years. A GitHub fine-grained token is one static credential scoped to one repository.
- **A tiny server of our own (a Cloudflare Worker + KV).** A server to maintain, against the "runs 10+ years untouched" rule.
- **A passphrase you type instead of a generated secret.** The token has to be pasted anyway, so one pasted string is simpler, and a random 256-bit secret can't be weak. A passphrase can be added later as a `kyoshi2.` key format without changing the files.
- **Encrypting nothing (the repository is private anyway).** GitHub staff, a leaked token, a mis-click making the repository public: encryption makes all of those harmless.
- **One file per device per app (the folder's layout) vs. one file per app.** One file per app, guarded by GitHub's own version check (the file's `sha` on write): the repository then holds one canonical copy of each app, exports are simple, and a clash (two devices saving the same app at the same moment) is just "read again, combine, save again".

### 2.1 The key (`core/cloud-crypto.js`, new, `K.cloudCrypto`, ~130 lines, no UI, no network)
- **The string:** `kyoshi1.<owner>/<repo>.<token>.<secret>`. `kyoshi1` names the format; the secret is 32 random bytes (`crypto.getRandomValues`) as base64url without padding (43 characters). Parse from the end, since repository names may hold dots: `parseKey(str)` → `{ repo: "owner/name", token, secret: Uint8Array }` or `null`; trim whitespace and line breaks first; owner `/^[A-Za-z0-9][A-Za-z0-9-]*$/`, name `/^[A-Za-z0-9._-]+$/`, token `/^[A-Za-z0-9_]+$/` (`github_pat_…` or `ghp_…`), secret 43 base64url characters. `makeKey({ repo, token, secret })` → the string. A refused paste gets a one-line reason ("That's a token on its own: paste the whole key, which starts with kyoshi1.").
- **Crypto:** `importKey(secret)` → `crypto.subtle.importKey("raw", bytes, "AES-GCM", false, ["encrypt", "decrypt"])`. `seal(obj, key, app)` → the envelope below: JSON → UTF-8 (`TextEncoder`) → gzip when `CompressionStream` exists (`"gzip"`, as `pdf-write.js deflate` does with `"deflate"`), else none → `crypto.subtle.encrypt({ name: "AES-GCM", iv }, key, bytes)` with a fresh 12-byte random `iv` each time → base64. `open(envelope, key)` → the object: checks `kyoshi === 1` and `alg`, base64 → decrypt (an `OperationError` means the wrong key or a changed file: throw `{ code: "key" }`; anything else `{ code: "format" }`) → gunzip when `zip === "gzip"` (`DecompressionStream`) → JSON. Reading accepts `zip: "gzip" | "none"` forever. `sealBytes(bytes, key)` / `openBytes(bytes, key)` for Phase 3's binary files: magic `KYO1` (4 bytes) + iv (12) + ciphertext, no compression (JPEG and PDF don't shrink).
- Helpers: base64 ↔ bytes in chunks of 0x8000 (a `String.fromCharCode(...big array)` overflows the call stack), base64url for the secret, UTF-8 both ways. `supported` = `!!(window.crypto && crypto.subtle)` (true on https and on a page opened from disk; false on plain http: "Cloud sync needs the site over https, or Kyoshi opened from a file").
- **The envelope** (`data/<app>.json` in the repository; a text file, self-describing for whoever reads it in ten years):
  ```json
  { "kyoshi": 1, "app": "momo", "alg": "AES-256-GCM", "zip": "gzip", "iv": "<base64, 12 bytes>", "data": "<base64 ciphertext>" }
  ```
  Its plain content is the save `K.sync.saveOf(A)` makes (the folder's file: `build()` + `savedAt`, `sync: { device, clock }`, `meetings`), so Import JSON takes a decrypted file as it is and the engine's `incorporate` merges it unchanged.

### 2.3 The GitHub client (`core/github.js`, new, `K.github`, ~120 lines, no UI, no crypto)
- `K.github.client({ repo, token })` → `{ repo(), listDir(path, etag), getFile(path), getBlob(sha), putFile(path, base64, { sha, message }), deleteFile(path, sha, message), branch(), newCommit(treeSha, message), moveBranch(sha) }` (the last three for Phase 4). One `request(method, path, { body, etag })` behind them: `fetch("https://api.github.com" + path, { method, headers, body, cache: "no-store" })` with `Accept: application/vnd.github+json`, `Authorization: Bearer <token>`, `X-GitHub-Api-Version: 2022-11-28`, `If-None-Match: <etag>` when given (a 304 comes back with no body: return `{ status: 304 }`). Reads `etag`, `x-ratelimit-remaining`, `x-ratelimit-reset` from the response.
- Errors are one class, `GithubError { status, code, until }`, `code` one of `"auth"` (401: the token is refused), `"forbidden"` (403 without the rate limit headers at zero: the token lacks the permission, or the repository's rules refuse), `"ratelimit"` (403 or 429 with the remaining count at 0: `until` = the reset time), `"notfound"` (404: no such repository, or the token can't see it, or the path doesn't exist: the caller decides), `"conflict"` (409: the file changed since it was read), `"invalid"` (422), `"server"` (5xx), `"network"` (`fetch` threw: offline, a network that blocks GitHub, or CORS refused). `listDir` turns 404 into `[]`; `getFile` returns `{ sha, size, bytes }`, stripping the line breaks GitHub puts in its base64 and, when `content` is empty because the file is over 1 MB, fetching it through `getBlob(sha)`.
- **Verify in the first smoke test from disk and note the answer in the file's header:** a `PUT` whose `sha` is stale answers 409 (treat 409 and 422 both as "read again, then try again"); the API answers CORS from a `file://` page (`Access-Control-Allow-Origin: *`, the `Authorization` header allowed in the preflight; `ETag` and `X-RateLimit-*` exposed). Both are documented GitHub behaviour; this environment couldn't reach the docs to quote them.

### 2.4 The transport (`core/cloud.js`, new, `K.cloud`, ~320 lines, no UI: it calls `K.cloudUI.render()` as the folder calls `K.backup.render()`)
- **Where the key lives:** localStorage `kyoshi.cloud` (add it to `storage.js`'s `PREFS`, so it's never taken for data) = `{ key, at, remember: true }` where `at` = `location.origin + location.pathname`; with *Remember on this device* unticked the same record goes to `sessionStorage` instead (gone when the tab closes; checked first). A record whose `at` isn't this page's is left alone and the state is `"off"` with the hint "A cloud key saved here belongs to another copy of Kyoshi; enter it again to use it with this one" (so a Download ZIP trial copy never pushes into the real repository by accident).
- **State:** `"off"` (no usable key), `"on"`, `"needs-key"` (the token or repository refused: `auth`, `forbidden`, `notfound` on the repository itself; message says which and what to do), `"error"` (a file can't be read with this key, or isn't an app's save: message names the app). Plus `busy` ("Saving Momo…", "Loading…"), `waiting` (how many apps have changes not yet in the cloud), `checkedAt`, `offline` (`!navigator.onLine`, or the last request was `network`: "Waiting for a connection" — not an error, not attention). Test mode: nothing runs (`K.testMode` checked where the folder checks it); `stopTimers()` from `K.dev.travel`.
- **Per app:** `A._sync.cloud = { sha: "", queued: false, timer: 0, note: "" }` (`sha`: the blob sha of `data/<app>.json` this device last read or wrote; the listing's `sha` is the same blob sha) and, in `meta` (stored under the app's `sync` key, additive), `pushed`: this device's own counter (`K.sync.version(A)`) at its last successful push (`loadMeta` reads it: `isPos(s.pushed) ? s.pushed : 0`). The app has unsent changes when `version(A) > meta.pushed`. Nothing else in `meta` changes; an older Kyoshi ignores the field.
- **Polling:** `CLOUD_CHECK_MS = 60000` while the page is in view, plus the engine's `request()` on focus/visible, and the `online` event. One `listDir("data", etag)` per poll (304 → nothing); for each app with a listed sha ≠ `cloud.sha`, or with unsent changes, `request(A)`. Apps run one at a time through one promise queue (as the folder's `task`), and the whole pass runs inside `navigator.locks.request("kyoshi-cloud", { ifAvailable: true }, …)` when the API exists, so two tabs of the same browser don't push at once (without locks the sha check still keeps it safe).
- **A pass for one app:** (1) if the listed sha ≠ `cloud.sha`: `getFile` → `open` → `A.data.looksLike(raw)` must hold → `K.sync.incorporate(A, raw)` → `K.sync.settle(A, data)` → `cloud.sha = sha`, note "Loaded from the cloud at 3:04 PM" / "Combined changes with the cloud's at …" (`result.what`) or nothing when `incorporate` returns null. (2) If `version(A) > meta.pushed`: `seal(K.sync.saveOf(A))` → `putFile("data/<app>.json", base64(envelope JSON), { sha: cloud.sha || undefined, message })` → `cloud.sha = result.content.sha`; if `version(A)` is still what was sealed, `meta.pushed = version` and `K.sync.storeMeta(A)`, `K.backup.setUnsaved(A, false)`; note "Saved to the cloud at …". On `conflict` or `invalid`: refresh the listing and run the pass again, at most 3 times, then note "The cloud was busy; trying again soon". Data comes in before it goes out, so a pull never overwrites a push and a push never loses a pull (the engine's counters decide, as with the folder).
- **A change:** `changed(A)` debounces `CLOUD_PUSH_DELAY_MS = 4000` then `request(A)`; `flush()` (pagehide, hidden) cancels timers and runs the passes now; one cut off by a closing tab is harmless: `pushed` persists, and the next start pushes.
- **Errors:** `auth`/`forbidden`/`notfound` on the repository → `setState("needs-key", message)`, polling stops until a new key ("GitHub no longer accepts the token in your key (expired or revoked). Make a new token with the same settings and tap Update token…, then paste the new key on your other devices." / "That repository can't be found with this token."). `ratelimit` → wait until `until` (note "GitHub asks us to wait until 3:20 PM"). `network`/`server` → back off: 30 s, doubling to 10 min, reset by a success; no console line (phones drop off all the time; the note says it). `key`/`format` or `looksLike` false → `setState("error", "The cloud's file for Momo can't be read with this key…")` and **no push of any app** until the key is entered again or the device is disconnected (a push over an unreadable file would leave the other devices unable to read it). `console.error` once per transition into `needs-key` or `error`, never the key, token or repository name.
- **Connecting:** `connect(keyString, remember)` (Enter key…): parse → `client.repo()` must succeed and say `private: true` (else "That repository is public: make it private first, then try again") → `listDir("data")`: if any file is there, `getFile` the first and `open` it to prove the secret ("That key doesn't fit the data already in that repository") → store the key → `cloud.sha = ""` and `meta.pushed = 0` for every app (the first pass pulls everything and combines, exactly as choosing a sync folder does today, then pushes every app with data) → state on → `request()`. `setup({ repo, token, remember })` (Set up a new cloud…): the same checks, plus `data/` must hold nothing ("That repository already holds Kyoshi data: use Enter key with the key you made for it, or empty it first") → make a secret → write `KYOSHI.md` → store → returns the key string for the UI to show. `updateToken(token)`: keep repo and secret, swap the token, `client.repo()` must succeed → store → returns the new key string. `disconnect()`: `confirm`, forget the key (both storages), state off, timers stopped; data and the repository stay. `syncNow()` = `request()` with the backoff reset.
- Exports: `init, state, message, status() → { state, message, busy, waiting, checkedAt, offline, repo }, note(A), keyString(), connect, setup, updateToken, disconnect, request, flush, stopTimers, changed, syncNow, exportDecrypted, decryptFile` (2.7), registered with `K.sync.use`. `init()` reads the key record and, when usable, goes straight to `"on"` and requests a pass (nothing on the network until then). `bugs.js`'s env line reads `sync ${K.sync.state()} · cloud waiting ${n}` (state words only).

### 4.1 A tidy history (`K.cloud.tidy()`)
- Every save is a commit, and encrypted files don't shrink in Git's history, so the repository grows by each save's size (a few tens of KB after gzip; a few hundred MB a year at worst). `tidy()`: `client.branch()` → the head commit's tree sha → `newCommit(treeSha, "Kyoshi: tidied the history")` with no parents → `moveBranch(sha)` (force). The files don't change (same blob shas, so no device re-pulls); the old commits become unreachable and GitHub frees the space over time. A **Tidy history** button in the Cloud block with the hint "Keeps today's files and drops the older versions, so the repository stays small." Automatic (D4) once the branch holds more than `TIDY_AFTER = 2000` commits: counted once a day in the poll from `GET /repos/{o}/{r}/commits?sha=<branch>&per_page=1`'s `Link` header (`rel="last"`'s page number is the count). Before the first automatic tidy, say so once in the block's text.
- **Verify in a smoke test:** the three Git Data calls work with a fine-grained token holding only *Contents: read and write* (they should; if `moveBranch` is refused, the button says so and the automatic tidy stays off).

### 4.2 The token's expiry
